Engine Specification & Technical Internals

1. 64-Bit Bitboard Representation

The 7×6 grid is packed into two 49-bit integer bitmasks (position and mask) across a 64-bit BigInt. Each column occupies 7 bits (6 playable rows plus 1 sentinel zero bit at the top). Terminal win verification executes in 4 bitwise shifts and AND operations in sub-2-nanosecond time, completely eliminating loops and array lookups.

2. Negamax Search with PVS

The engine leverages zero-sum mathematical symmetry: NegaMax(s, α, β) = max(-NegaMax(s', -β, -α)). Under Principal Variation Search (PVS), candidate moves are pre-sorted by heuristic priority. The primary move is searched with a full [α, β] window, while all remaining siblings are evaluated using null-window scout searches [-α - 1, -α] to force aggressive beta-cutoffs.

3. Dynamic Move Ordering & Transposition Caching

  • Zobrist Incremental Hashing: State updates execute in O(1) via XOR bit manipulation.
  • Transposition Cache: 600,000 entries caching exact evaluations, upper bounds, and lower bounds to eliminate redundant subtree evaluation.
  • Killer & History Heuristics: Dynamically elevates non-capture moves that induced beta-cutoffs in sibling branches.
  • Center Proximity: Prioritizes central columns [3, 2, 4, 1, 5, 0, 6] controlling up to 16 winning alignments.

4. Web Worker Threading

Search computation is completely decoupled from the DOM. A dedicated Web Worker executes tree traversal on a background thread while posting progress metrics to the main UI thread, preserving a 60 FPS animation loop during deep plies.
